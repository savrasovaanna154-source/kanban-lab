# Чек-лист тестирования

Чек-лист используется при приёмке работы и перед релизом. Каждый пункт должен быть отмечен `[x]` после прохождения.

## 1. Функциональное покрытие

- [ ] Регистрация, вход, выход работают.
- [ ] JWT выдаётся и проверяется на защищённых эндпоинтах.
- [ ] Роли (admin / manager / developer) разграничивают доступ.
- [ ] CRUD проектов, досок, колонок, карточек реализован.
- [ ] Перемещение карточек drag-and-drop сохраняется в БД.
- [ ] WIP-лимит блокирует превышение.
- [ ] Поиск и фильтры (исполнитель, метки, приоритет) работают.
- [ ] История действий ведётся.

## 2. API

- [ ] Все эндпоинты покрыты интеграционными тестами.
- [ ] Swagger UI доступен по `/api-docs` и актуален.
- [ ] Коды ошибок соответствуют REST-конвенциям (400, 401, 403, 404, 409, 500).
- [ ] Валидация входных данных через Zod подключена ко всем POST/PATCH.

## 3. E2E

- [ ] Сценарий регистрация → вход → проект → доска → карточка → move → выход проходит.
- [ ] E2E работают в Chrome, Firefox, Edge.
- [ ] Скриншоты и трейсы сохраняются при падении.

## 4. Нагрузка

- [ ] k6-тест выдерживает 1000 RPS.
- [ ] p95 времени отклика < 200 мс.
- [ ] Ошибок менее 1% при целевой нагрузке.

## 5. Безопасность

- [ ] OWASP ZAP: нет уязвимостей уровня High.
- [ ] `npm audit --production`: нет Critical.
- [ ] Пароли хешируются bcrypt (cost ≥ 10).
- [ ] Заголовки helmet настроены (CSP, X-Frame-Options, HSTS).
- [ ] Отсутствуют SQL-инъекции (Prisma parameterized queries).
- [ ] XSS: пользовательский ввод санитайзится, экранируется.

## 6. Качество кода

- [ ] Покрытие тестами ≥ 80% строк.
- [ ] Покрытие тестами ≥ 70% ветвей.
- [ ] Линтер и типизация проходят без ошибок (`npm run lint`, `tsc --noEmit`).
- [ ] Нет `any` в публичных API-типах.
- [ ] ESLint и Prettier согласованы.

## 7. CI/CD

- [ ] GitHub Actions запускает все тесты при push.
- [ ] Пайплайн: lint → unit → build → integration → e2e → security → deploy.
- [ ] Отчёт покрытия загружается в Codecov.
- [ ] Артефакты (Playwright-трейсы, HTML-отчёты) сохраняются.
- [ ] Деплой на staging выполняется автоматически из main.

## 8. Документация

- [ ] README содержит инструкцию по запуску.
- [ ] Документация API (Swagger) актуальна.
- [ ] План тестирования (`TEST_PLAN.md`) заполнен.
- [ ] Тест-кейсы (`TEST_CASES.md`) заполнены.
- [ ] Баг-репорты (`BUG_REPORTS.md`) оформлены по шаблону.
- [ ] Итоговый отчёт (`TEST_REPORT.md`) заполнен.
- [ ] Обоснование выбора стека (`STACK.md`) оформлено.
- [ ] Архитектура (`ARCHITECTURE.md`) описана.
- [ ] Презентация (10–15 слайдов) готова.

## 9. Готовность к защите

- [ ] Демонстрация приложения подготовлена.
- [ ] Демонстрация автотестов подготовлена (показ зелёного CI).
- [ ] Ответы на типовые вопросы: почему такой стек, какие баги нашли, как обеспечено покрытие.
- [ ] Репозиторий публичный, доступен преподавателю.
