## Детализация сложных кейсов

### TC-03. Перемещение карточки между колонками

**Предусловия:**
- Пользователь аутентифицирован как manager.
- Есть проект с доской, на доске минимум две колонки: To Do и In Progress.
- В колонке To Do есть карточка с id = card-1.

**Шаги:**
1. Открыть доску в браузере.
2. Захватить карточку card-1 мышью.
3. Перетащить её в колонку In Progress.
4. Отпустить мышь.

**Ожидаемый результат:**
- Карточка отображается в колонке In Progress.
- PATCH /api/cards/card-1/move возвращает 200.
- В БД поле columnId карточки = id колонки In Progress.
- В аудит-логе есть запись move с автором.

### TC-04. Права доступа

**Предусловия:**
- Пользователь с ролью developer.
- Существует проект, принадлежащий другому пользователю.

**Шаги:**
1. Открыть список проектов.
2. Попытаться удалить чужой проект через UI.
3. Вызвать DELETE /api/projects/:id через API-клиент.

**Ожидаемый результат:**
- В UI кнопка «Удалить» недоступна.
- API возвращает 403 Forbidden.
- Проект остаётся в БД.

### TC-07. WIP-лимит

**Предусловия:**
- Колонка In Progress с wipLimit = 1.
- В колонке To Do две карточки.

**Шаги:**
1. Переместить первую карточку из To Do в In Progress.
2. Переместить вторую карточку из To Do в In Progress.

**Ожидаемый результат:**
- Первое перемещение проходит успешно.
- Второе блокируется, появляется предупреждение «Превышен WIP-лимит».
- В БД вторая карточка остаётся в колонке To Do.

### TC-13. XSS в описании

**Шаги:**
1. Открыть создание карточки.
2. В поле description ввести `<script>alert(1)</script>`.
3. Сохранить карточку.
4. Открыть карточку.

**Ожидаемый результат:**
- Скрипт не исполняется.
- В DOM текст отображается как строка.
- В БД хранится сырой текст, sanitize применяется на отображении.

### TC-14. SQL-инъекция в поиске

**Шаги:**
1. Открыть поле поиска.
2. Ввести `' OR 1=1 --`.
3. Нажать Enter.

**Ожидаемый результат:**
- Запрос обрабатывается параметризованно (Prisma).
- Результат — пустая выборка.
- В логах нет SQL-ошибок, сервер отвечает 200.
